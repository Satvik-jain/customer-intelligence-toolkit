# Synthetic panel protocol

## 1. State the scenario

Record the decision question, target population, geography, product maturity, stimulus, alternatives, purchase context, and what the simulation is not intended to establish.

## 2. Set profile coverage

Use segment definitions and evidence to select profiles. Explain why each profile is included. Treat profile count as exploratory coverage, not sample size. Do not add synthetic profiles to manufacture apparent precision.

## 3. Standardize the task

- Present the same stimulus and response questions to each persona.
- Include relevant alternatives and a no-choice option.
- Vary one factor at a time for comparisons when feasible.
- Do not lead the persona toward a preferred response.
- Keep individual responses isolated unless interaction is the research question.

## 4. Elicit decision-relevant outputs

Ask for the choice or no-choice response, the condition that most affects it, likely objections, missing information, and a concise generated explanation. Treat the explanation as model output, not a verified causal account.

## 5. Record setup

Record model and version when known, run date, prompt/scenario version, persona basis, grounding data, available seed/sampling settings, and any retrieval sources.

## 6. Report carefully

Show individual variation and disagreement. Summarize themes as patterns within this simulation, not population estimates. Label every response and aggregate as [SYNTHETIC SIMULATION]. Turn decision-relevant observations into hypotheses for real research.

## Source note

This panel protocol is project-authored operational synthesis, not a standardized research instrument. Published simulation studies are narrow tests of specified models, tasks, and populations; see [verified source notes](../../../references/sources.md#synthetic-customer-simulation-and-evidence-limits).
